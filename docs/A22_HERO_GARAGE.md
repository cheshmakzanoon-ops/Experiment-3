# A22 — Aurel working garage, revision 01

## Implemented scope

One authored bay replaces the procedural bay at index 4 (displayed **05**), centred at track station 106 m and lateral offset 35 m. The other eleven bays remain unchanged. This is a scenery and asset-pipeline implementation, not a change to pit-service rules, collisions, vehicle placement or the supplied player car/cockpit/driver.

The open architectural shell includes recessed wall cassettes, structural portal columns, upper glazing, a roller-shutter cassette and guide channels, fitted drawer cabinets and worktops, overhead cupboards, rear service door, monitor housings, lighting diffusers, ceiling cable trays, conduit, stowed hose reels, an electrical enclosure, drainage grates, rooftop ventilation and original Aurel signage. Moveable equipment and personnel are deliberately not baked into the garage.

## Source and shipped assets

- Editable source: `scripts/aurel-hero-garage-bay.blend`.
- Reproducible authoring script: `scripts/author-garage.py` (Blender 5.2.2 LTS).
- Shipped self-contained export: `public/models/aurel-hero-garage-bay.glb`.
- Integrity, geometry and placement receipt: `src/rendering/hero-garage.manifest.json`.
- Owned loader and presentation: `src/rendering/hero-garage.ts`.

The GLB is 6,285,924 bytes, with 12 materials and two original embedded 256 x 256 micro-surface maps. Authored detail levels contain 39,444 / 20,752 / 3,780 triangles. Runtime geometry is material-batched, not submitted as one object per drawer or fastener. Nine named sockets are retained for the car, front jack, four wheels, two engineers and crew. Sockets are placement metadata; no live racing car is teleported into the garage.

The runtime factory loads the asset before cooperative circuit construction, checks its byte budget, SHA-256 and GLB contract, and exposes a loading error rather than silently substituting the old bay. Static batching preserves the LOD/socket hierarchy. LOD selection uses lens-aware distance to the building bounds and hysteresis. Mirrors reuse the main-view representation. Existing lights, fog and environment illuminate the materials; diffuser emission follows day/sunset/night. No new shadow-casting lights or rendering passes are added.

## Validation and reproduction

The authoring workflow generated the GLB independently and reproduced its exact SHA-256: `653b922595533be6cda5bda1f96b90e738d6eac3f403e0dc37f6437f30383ff0`. GitHub run `36560189407` retains the source/export receipt. Blender file save metadata need not be byte-identical across hosts.

Seven unit cases cover provenance, corruption/truncation, sockets, bounds, actual central-passage ray intersections, LOD and batching preservation, disposal, and bounded/cancelled transfer. CPU geometry tests intentionally stub texture decoding; browser surveys decode the actual embedded images.

```sh
blender --background --factory-startup --python scripts/author-garage.py
npm ci
npm test -- tests/hero-garage.test.ts
npm run check
npm run test:e2e -- e2e/43-hero-garage.spec.ts e2e/26-aurel-environment.spec.ts
```

The dedicated browser workflow tests normal application loading through practice entry and captures three views of the actual circuit in day, sunset and rainy night conditions. It checks unchanged simulation/water data, stable repeated-render allocations, bounded added submissions and WebGL errors. These fixed engineering cameras are distinct from a driven lap and do not replace the main CI gates.
