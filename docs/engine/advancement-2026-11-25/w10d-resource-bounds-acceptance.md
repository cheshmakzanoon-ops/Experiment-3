## 2. Fixed reuse is separate from accumulated history

The surface additions contain ten Float64 values per cell: one depression value, two water-bank values, one rainfall key and six matrix coefficients. Therefore `512 × 7 × 10 × 8 = 286,720` bytes. This excludes existing surface state, scalar keys, typed-array headers and the lane index. The covered thermal solver retains its scalar path without a second per-cell matrix bank. Water coefficients compare the current timestep and actual drainage value; thermal coefficients compare the actual matrix signature and rainfall key. Ambient, solar and evaporation forcing still refresh. No history of weather keys is appended to a map. [Coefficient tests](../../../tests/engine-surface-coefficients.test.ts) exercise fixed storage, repeated slots and mutable inputs; the [independent cache review](w08a-physics-cache-review.md) preserves arithmetic and validation boundaries.

Paved lane eviction is finite even for a roaming workload, but caching remains a tradeoff: misses allocate candidate arrays and perform the conservative construction work. The [lane evidence](w07a-lane-measurement.md) retains the slower all-miss case rather than inferring a universal benefit. Geometry is an immutable input to this index; arbitrary mutation of authored points is not a supported cache-invalidation contract. Existing MX/SX behavior is unchanged and must not be included in the new 2,048-entry claim. [Lane tests](../../../tests/engine-paved-lane-index.test.ts).

The audio basis is deliberately retained. A short cold input does not force its construction, an authored 40-element input creates it, and longer public inputs follow the original calculation without expanding the basis. Once warm, shorter inputs may reuse it. The profile WeakMap has no explicit eviction API: profiles retained by the application retain their cached wave arrays. The basis saves repeated trigonometry at a documented cold-start and memory cost; it is not a leak-removal claim. [Basis tests](../../../tests/engine-loudness-sine-basis.test.ts), [audio measurements](w07d-audio-measurement.md).

The ghost index likewise adds bounded payload rather than reducing recorded pose storage. Validation limits recordings to fewer than 600 seconds and at most 18,002 samples. A nonmonotonic player builds one prefix-maximum Float32 array; strictly increasing distance needs none. The recording remains unchanged, and neither seeking nor `timeAt` appends history. The recorder discards an ineligible or over-duration lap and recovers at the next lap/reset. Constructor callers must continue to supply a validated recording. [Ghost bounds](../../../tests/engine-ghost-bounds.test.ts), [first-passage tests](../../../tests/engine-ghost-first-passage.test.ts), [record-boundary review](w08c-storage-records-review.md).

Flashback requires a different statement. The supported modes resimulate from the session start, so their `InputLog.entries` is session-long. Deduplication reduces repeated unchanged controls, but varying controls, pit commands and autopilot changes can keep growing the journal. A rewind copies the entries array for its resimulation and truncates the resumed future afterward. The five-use UI limit and 30-second destination window do not remove that original history requirement. The new change removes the journal entirely only for time trial and qualifying. The retained worker fixture covers **36,000 varying samples and 72,000 physics ticks**, with zero entries in both unsupported modes and exact recordings against its retained-history control. [Disabled-history test](../../../tests/engine-flashback-disabled-history.test.ts), [worker](../../../src/workers/physics.worker.ts). Supported-mode history compaction would require a separate checkpoint/resimulation design and equivalence proof.

## 3. Page, session and callback owners

Persisted `pagehide` and terminal departure have different obligations. The retained page cancels scheduled presentation and input polling, suspends menu cues, neutralizes input and pauses the worker while keeping the active session resources. Unfinished startup candidates are revoked separately. `pageshow` resets clocks and input baselines and creates fresh scheduled owners; old epoch callbacks cannot resume an old visit. Gameplay remains paused until the supported player resume path. A final departure revokes host ownership before independently attempting cleanup of workers, rendering, input, UI, replay/export and audio. One synchronous child cleanup failure does not prevent the remaining release attempts. Asynchronous replay/audio cleanup is observed, not synchronously guaranteed to have finished when `dispose()` returns. [Host](../../../src/main.ts), [Festival session](../../../src/session/free-roam.ts), [lifecycle tests](../../../tests/engine-page-lifecycle.test.ts).

The [native history attachment](evidence/checkpoint-774e62f/native-page-history.json) records two trusted BFCache cycles. Each hidden owner has zero scheduled frames and input intervals; each restored owner has one of each. The same document/worker identities survive both cycles. Paused ticks remain **57 → 57** and **95 → 95**. Request accounting balances to zero, with no duplicate, untracked or stale-owner frame deliveries. The terminal reload records zero old frames/intervals and exactly one renderer disposal, worker termination, input disposal, UI disposal, race-audio disposal and cue disposal. The replacement has new document and worker identities.

These observations apply to the native fixture using actual host lifecycle methods, worker and context. Its minimal UI does not establish that every real game route is BFCache-eligible. It is also incorrect to infer duplicate scheduling from equal browser timestamps: the fixture records legitimate equal timestamps, while request identities show one frame call per request. The finite two-cycle result is not a long-session soak.

Menu and credits components have independent RAF generations. Repeated pageshow, cancellation followed by late delivery, disposal and device replacement cannot create an additional owned polling chain. Input reset clears queued shifts, held keyboard state and touch ownership, releases observed pointer capture, and fresh device samples baseline held buttons. Menu navigation keeps the existing **360 ms initial / 110 ms repeat** cadence without replaying missed repeats. The modal operation token additionally prevents a disposer returned after synchronous focus/cue replacement from becoming the live binding. [Device composition tests](../../../tests/engine-device-lifecycle-composition.test.ts), [modal opening tests](../../../tests/engine-ui-opening-review.test.ts), [Interface](../../../src/ui/interface.ts). Native gamepad inputs remain scripted; physical controller behavior was not measured.

## 4. GPU admission and publication

Context identity owns completion state. Multiple renderer wrappers acquire leases on the same gate, so disposing a borrower cannot erase pending work needed by another wrapper. Releasing the final lease removes the WeakMap entry before driver cleanup, making repeated release idempotent even if cleanup fails. Gate polling uses a zero timeout and never calls `gl.finish()`. Ordinary presentation admits no new frame until observed completion. Explicit preparation submissions may replace the stored fence because a later fence covers preceding commands; this is not permission for ordinary frames to bypass admission. [Gate implementation](../../../src/rendering/gpu-frame-gate.ts), [shared ownership tests](../../../tests/engine-shared-gpu-ownership.test.ts).

The stall contract is also narrower than a blanket wall-clock timeout: the gate accumulates continuous active polling and resets that accumulation across long gaps. Festival preparation applies its default **90,000 ms timeout separately to each `waitForGpu()` invocation**, checked between browser-task yields. It is not a single total preparation deadline, cannot preempt blocked JavaScript and does not independently bound compilation. Deadline expiry does not invent GPU completion or release another owner's fence. [Festival renderer](../../../src/rendering/open-world/festival-renderer.ts).

The [native shared-fence evidence](evidence/checkpoint-774e62f/native-gpu-shared-fences.json) shows fences **1, 2 and 3** each deleted once. Two completed; the third was released at final ownership teardown. No `finish` call occurred. Both strict red/green images match all **256 bytes**, and final recorded Three geometry, texture and program counts are zero. The gate witness explicitly uses a test-only `vec4` uniform. The separate MeshBasic and raw-`vec3` diagnostics still each differ in **64 of 256 bytes** through all three read methods. These limitations remain in the accepted artifact; finite resource cleanup does not certify those material paths, full-game image equivalence or a physical GPU. [Native audit](w09c-native-evidence-audit.md).

Dirty-range publication is bounded independently. The current helper merges the last compatible span cheaply and normalizes the actual public list only when capacity is threatened. A seventeenth truly disjoint union triggers a full upload; duplicate or bridging work can still fit. A full range remains sticky until publication. Direct external edits to `updateRanges` are observed, and no auxiliary metadata can drift from them. This bounds pending helper state while preserving actual Three upload coverage. [Range tests](../../../tests/engine-attribute-range-coalescing.test.ts), [native uploads](evidence/checkpoint-774e62f/native-gpu-attribute-uploads.json).

Festival pause/photo pacing targets 15 Hz only after GPU admission. It still services the live HUD, controls and audio on the allowed host callback path. Skipped or declined draws do not consume a new resize/redraw revision; reentrant travel, page changes or disposal revoke the remainder of the old frame. This reduces submission work without claiming fewer physics ticks or a fixed total frame cost. [Pacing tests](../../../tests/engine-festival-frame-pacing.test.ts).

## 5. Audio, packet and recording ownership

UI sound suspension first clears the live context, graph and cue references, then cancels each old voice, disconnects bus nodes and requests context close. This ordering lets a later deliberate cue create a fresh graph without an old resume reviving voices. Disposal additionally aborts event listeners and is terminal. Each branch is owned during partial construction, so a failed later allocation is also released. The six sound identities have a 45 ms per-sound throttle; that and finite authored envelopes are not an explicit maximum live-voice count under arbitrarily delayed browser events. [UiSounds](../../../src/audio/ui-sounds.ts), [lifetime tests](../../../tests/ui-audio-lifetime.test.ts).

The [native suspension attachment](evidence/checkpoint-774e62f/native-audio-advancement-suspension.json) records three contexts, one fulfilled close request each, and **10/10, 10/10 and 17/17** nodes disconnected. Final cue count is zero and every observed source handler is cleared. The replacement received three native `ended` events; controlled old callbacks did not revive a cue. The abandoned old resume promise remains observably pending after closure, replacement completion and final disposal. Acceptance relies on graph release and close outcomes, not on falsely requiring that promise to settle. This fixture does not certify audio hardware or all browser scheduling behavior.

Network packet ownership is explicit. `ByteWriter.finish()` slices an independent buffer. Snapshot preparation shares captured car bytes only inside one broadcast; every recipient packet is encoded before any transport callback can reenter. The dispatch latch permits the initial batch and one reentrant follow-up, then coalesces further requests into scheduled work. Selected recipients are capped by the existing 12-player lobby contract, and arbitrary codec callers retain the separate 32-car validation limit. The new input capacity removes growth for valid packets but still allocates writer and finished packet buffers. [Server](../../../src/net/server.ts), [codec](../../../src/net/codec.ts), [limits](../../../src/net/constants.ts), [batch tests](../../../tests/engine-snapshot-batch-encoding.test.ts).

The [native network evidence](evidence/checkpoint-774e62f/native-network-advancement.json) observes **768 detached sender buffers, 768 unique received buffers and 94,945 matched bytes**. Six retained receiver buffers remain unchanged. Cleanup closes six ports with zero pending native work or events. The client snapshots packet byte length before an owning transfer detaches it, and counts only successful sends. This verifies the selected native MessageChannel transport contract; it does not set a memory budget for a third-party transport's retained packets. [Transfer accounting test](../../../tests/engine-transfer-transport-accounting.test.ts).

Telemetry continuity is about interpreting bounded records, not expanding capture storage. `completeLaps` now includes the closing sample gap while keeping validity ownership in `[start, i)`. A partial oldest lap after ring wrap is excluded, and a bad following lap does not invalidate the previous lap's validity flags. Export snapshots copy the current ring, so transferring export bytes does not detach the recorder. One export owner cancels its predecessor, terminates its worker and ignores obsolete replies. [Telemetry export](../../../src/storage/telemetry-export.ts), [lap-gap tests](../../../tests/engine-telemetry-lap-gap.test.ts).

The [native records attachment](evidence/checkpoint-774e62f/native-records-closing-gap.json) exercises a **630-row, 228-channel ring with head 100**, a detached export copy, zero retained/exported value differences and capture-worker termination. Full-session replay remains a separate archival mechanism: its resident page/read/write limits do not cap metadata, all surface-record payloads or persistent session storage. Completion/cleanup depends on its storage promises and error handling. Those existing storage components were read for context, not redesigned or newly soak-tested by this assignment.

## 6. Release interpretation

The release can state that the added fixed caches stay fixed, the new paved cache is capped, unsupported flashback modes retain no journal, and the tested ownership transitions prevent obsolete callbacks and borrowed-resource teardown from corrupting their replacements. It can also state the exact observed native cleanup counts above.

It should retain these unresolved or intentionally broader boundaries: supported-mode flashback history still grows; replay metadata and archive storage grow; WeakMap reachability is not a collection measurement; UI cue cleanup depends on event/close behavior; external transport retention is outside the encoder; per-wait GPU deadlines cannot preempt a stalled task; physical GPU/controller/audio validation and a complete-game soak remain unperformed. The [broader failure classification](w09d-baseline-failure-classification.md) also prevents focused workflow success from being described as every repository workflow passing.
