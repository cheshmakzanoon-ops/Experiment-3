Branch `studio/legal-ip-hero-car`, cut from `main` at 4b66e0e; `main` at 2cc4438 (vehicle art 2) is merged in.

review; section 8 lists each blocker, what changed and what was run. Everything below was measured on this

## 2. Method

1. Enumerated every tracked and generated binary and authored asset (`git ls-files`, `public/`,
   `src/rendering/*.glb.gz`, `*.manifest.json`, `authoring/`, `reference/`, `tools/`, `playable/`,
   `screenshots/`, `docs/`) and what `vite build` copies into `dist/` (`public/` wholesale, imported
   assets, fonts).
2. Decoded every shipped GLB / gzipped GLB and read its JSON chunk (node, mesh, material, image
   names and `extras`) for brand markers (`scripts/ip-denylist.mjs`). Decompressed the zstd `.blend`
   sources of APX-01, the A61 assembly and the driver and listed their datablock names.
3. Grepped every text source under `src/`, `index.html`, `desktop/`, `package.json` for brand names
   (teams, sponsors, tyre / brake / fuel makers, motorcycle and car makers, series, commercial games)
   and read each hit to separate a string a player can see from a comment or an identifier.
4. Built the product bundle and the owner-only bundle and ran the guard on both, plus the committed
   `playable/` snapshot.
5. Read the provenance claims in `docs/ASSET_PROVENANCE.md`, the authoring scripts and the hash-pinned
   manifests, and compared them with what the binaries actually contain.

Limits: authorship ("original, authored by a script or by hand in Blender") is **self-attested** by
the repository (scripts, manifests, git history is a single squashed lineage). The scans show no brand
markers and no embedded third-party images; they cannot prove that a mesh was not modelled by looking
at a real object. Silhouettes, likenesses and trade dress are judgement calls for counsel, not greps.

## 4. What was changed

### 4.1 APX-01 is an original hero car (the blocker)

Investigation first: the renderer already builds every car, including car zero, as a `FormulaCar`;
car zero merely swapped its geometry for the supplied asset when that was loaded (`car.ts`
`suppliedAsset.take`). The same `FormulaCar` is what the game rendered for every opponent from the
original `apx01-shell` + A61 assets, so the original car already had a complete, tested rig (steering,
suspension, spin, pit service, damage, brake lights, mirrors, cockpit camera, driver arms from the
vehicle-art audit). The two procedural options were therefore not needed: the original authored
assembly is the better starting point (about 228 k triangles near, 41 mechanical roles) than the
procedural open-wheel catalogue builder (`vehicle-bodies/open-wheel.ts`, which builds the HF-67 /
HF-76 / HF-86 / JF-2 class cars and is a lower-detail, different-era layout; see the vehicle-art
report D6).

Changes:

- `src/rendering/renderer.ts`: the supplied model is loaded only behind a build flag; a product
  build loads the A61 levels for the player too (`rivalLevels` in the showroom as well), so the menu
  showroom, the grid and every camera show the original car.
- `src/rendering/car.ts`: car zero uses the authored A61 levels when no supplied asset is given;
  `setLivery` now also repaints the painted wheel covers (they kept the team-0 colour while the body
  followed the player's livery); the nose identity reads the team title (`VOLTEX / 07`), no legacy name.
- Hero livery (original, no real team uses it): electric violet `#5b2bd6`, indigo-black belly,
  volt accent `#d8ff3c`, metallic finish, `VOLTEX` title sponsor with fictional partners.
  `LIVERIES[0]`, `SCHEME_DETAILS[0]`, `DEFAULT_LIVERY`, `PLAYER_CREW_COLOUR` (the crew kit followed the
  supplied car's navy), preset `copper` -> `voltage`.
- Tyre brand `APEX CORSA` -> `MOTOBOUND` everywhere it is drawn (tyres, GP shells, wall prints, padding).

### 4.2 The supplied model is excluded from product builds

- `vite.config.ts`: `MOTOBOUND_SUPPLIED_PLAYER=1` selects an owner build. Otherwise: `__SUPPLIED_PLAYER__`
  is false, the plugin `owner-only-assets` removes `models/supplied-player*.gz` from the output after
  Vite copies `public/` and drops the orphan chunk Rollup leaves behind for a tree-shaken `import()`, and
  the owner-only modules are marked side-effect free so the dead branches take them (and every real name
  they carry) out of the bundle.
- `src/build-flags.d.ts`, `OWNER_BUILD` constants in `renderer.ts` and `car.ts`; the loader is a dynamic
  import behind the flag.
- `src/rendering/studio/supplied-decal-art.ts`: the real decal-sheet key table, moved out of the shared
  `brand-atlas.ts` into an owner-only module with a header saying so.
- `scripts/build-player-lods.mjs --owner-only` in `prebuild` / `predev`: a product build no longer
  generates the 4 MB LOD index it will not use (`pretest` still generates it for the unit tests).
- Verified both ways: product build has no `supplied-player*` file or chunk; an owner QA build contains
  both binaries and the chunk (checked in scratch builds, section 7).

**Build variants and the enforced guard** (rework, section 8). A build is exactly one of three variants,
recorded as `variant` in `BUILD_IDENTITY.json`:

| Variant   | Made by                                          | Contains                                     | Certifiable / publishable |
| --------- | ------------------------------------------------ | -------------------------------------------- | ------------------------- |
| `product` | `npm run build` (the only certifying path)       | the original authored APX-01, nothing owner  | yes, after the guard      |
| `owner`   | `npm run build:qa` (`MOTOBOUND_SUPPLIED_PLAYER`) | the real-brand supplied model, its LOD index | never                     |
| `review`  | `npm run build:qa` (`MOTOBOUND_REVIEW_TOOLS`)    | the commercial-game reference catalogue      | never                     |

- `vite.config.ts` (plugin `ip-guard`): every product build runs `scripts/ip-guard.mjs` on its output when it is
  written, so a brand name or an owner asset makes `npm run build` (and any `vite build`) fail. A QA build is
  labelled instead (`variant`, `NOT_FOR_RELEASE.txt`). Plugin `certifiable-build`: `npm run build` throws if
  `MOTOBOUND_SUPPLIED_PLAYER` or `MOTOBOUND_REVIEW_TOOLS` is set (it names `npm run build:qa`), so a QA
  variable cannot reach the certifying path by accident.
- `scripts/build-qa.mjs` (`npm run build:qa`): the only way to make a QA build; it sets both variables and
  `MOTOBOUND_QA_BUILD=1`, generates the owner LOD index, and never calls `tsc` or the guard.
- `scripts/ip-guard.mjs`: refuses an owner or review build outright (a `supplied-player*` file or chunk, or
  `variant` other than `product`): exit 1, "can never be certified, published, deployed or packaged". There is
  no flag, option or environment variable that certifies one: the old `--owner-build`, which exited 0, is
  removed (it now exits 2). A product build is scanned for brand names in every text file, GLB name table and
  gzipped asset (3 s on a 128 MB `dist/`).
- Where it runs: inside `vite build`; CI `validate` (`node scripts/ip-guard.mjs --dist dist`, before the
  `apex-formula-web` upload); CI `publish` on the downloaded artifact; `scripts/publish-validated-release.sh`
  (also requires `variant: "product"`); `desktop/scripts/stage-web.cjs` before packaging.
- The deny list matches **words**, not byte patterns (rule in the header of `scripts/ip-denylist.mjs`, pinned by
  `tests/ip-denylist.test.ts`): case, `_`, `-`, spaces, dots between words, camelCase humps and letter / digit
  boundaries are normalised, so `RB19_BODY`, `redbull_wordmark`, `tyre_pirelli`, `hard_rock`, `cash_app`,
  `tag_heuer`, `charging_bull`, `front_bull`, `arctic_wolf` and bare `oracle` / `honda` all hit. Generic words
  (`shell`, `bull`, `rock`, `bullet`, `mobility`, `oracles`) do not, other punctuation is a hard break, and
  random base64 or hash text is not split into accidental words. Limits: names that are ordinary words alone
  (`zoom`, `att`, `front_red`, decal keys of the owner model) cannot be caught by name; they exist only beside
  detectable keys and the owner binaries are refused by file. A shipped identifier containing the whole word
  `oracle` (`testOracle`) is a hit by design.

## 8. Rework after the independent review

The first version was rejected for five blockers. What each was, what changed, what is still open:

1. **B1, e2e specs crashed on the product build.** `42-full-scene-index-budget` and `a31-wheel-gun` dereferenced `view.cars[0].suppliedPlayer!`, and their ad-hoc vite
   bundles never defined `__SUPPLIED_PLAYER__`. Ported (section 4.5): 42 measures the authored player car in the real eight-car pass (its owner-only compaction half
   runs only in an owner build); A31 witnesses the authored wheel carrier with unchanged thresholds. Running them found three more problems, all fixed: the wheel gun
   sat 5.5 to 6.8 mm above the nut for every car, the owner model included (`pit-crew.ts`); the Graphics cockpit lens setting was ignored by the original car's cockpit
   (`renderer.ts`); the A31 startup test asserted pit tooling at the menu, which the lazy-showroom change (`ebc2e06`) no longer builds. All 107 ad-hoc bundles in 81 specs now define the flag from the
   environment (`fixtureDefine`), pinned by `tests/e2e-fixture-bundles.test.ts`. P0 cockpit framing's owner path is now real (verified on an owner build) and the same
   criteria run on the authored cockpit. Still open: the A31 `sunset` / `night` surveys and the other P0 groups were not run here (host), and the 100-odd other
   renderer-bundling specs were audited, not executed.
2. **B2, the guard was manual.** It is enforced in `vite build`, CI `validate`, CI `publish`, the release script and the desktop stager; owner and review builds can never
   pass it and `npm run build` refuses to make them (section 4.2). Still open: nothing stops a person zipping a QA build by hand.
3. **B3, the deny list missed snake_case and compounds.** Word-aware matching with a documented rule and a table-driven test (11 reviewer identifiers + 91 spellings
   must match, 85 innocuous strings must not). Limit: names that are ordinary words alone (`zoom`, `att`, `front_red`) cannot be matched by name.
4. **B4, merge `main`.** Done; the merge was textually clean but not semantically (stale copper default in `colourways.ts`); APX-01 renders the original authored car with
   vehicle art 2's catalogue colourways, drivers and livery plumbing alongside (`hero-car-original`, `vehicle-colourways`, `festival-vehicle-detail`, `driver-arms` pass).
   Players who saved the OLD default livery (copper) keep it as an explicit choice and see their hero car in copper until they pick `voltage`.
5. **B5, P19.** Green after the merge. The exemption is two files: the owner-only decal key table (`supplied-decal-art.ts`) and the wildcard-name deny list
   (`wildcard-validation.ts`), which has to spell the names it rejects; both are commented in the test.

**Open, ranked:** (1) four path-triggered workflows still run owner- or review-gated specs on a product build and skip (4.6, exact steps there); (2) A31 `sunset` / `night`
and P0 `controls` / `driving` / `braking` / `weather` on an idle host or in CI; (3) execute the other ad-hoc-bundle specs against the original car (CI browser shards do).
