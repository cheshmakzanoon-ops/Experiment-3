# Studio helper tools

Developer helpers used during the F1 25 look programme (see `docs/studio/`). Run from the repo root
(or a worktree with `node_modules` linked). Browser tools use SwiftShader through the system Chromium;
set `CHROMIUM_PATH` if Playwright cannot find one.

| File | Purpose |
|---|---|
| `capture.mjs` | Simple capture: menu, four cameras, driving. `node scripts/studio/tools/capture.mjs <out> --url http://127.0.0.1:<port>` |
| `qcap.sh` | Shader check then `scripts/studio/capture-matrix.mjs`, both under a capture lock. Scratch dir: `$STUDIO_SCRATCH` (default `$TMPDIR/apex-studio`). |
| `shadercheck.mjs` | Loads the build and fails on shader compile / page errors. |
| `menushot.mjs` | Front-end menu screenshots. |
| `uxshots.mjs` | Real-game menu screenshots at 1280x720, 1920x1080, 1024x600 and 390x844, plus the GP, dirt, festival and settings scenes (JPEG). |
| `uxdom.mjs` + `ux-fixture.ts` | Fast DOM-only screens of the real Interface (menu per discipline, pause, results, settings, controls, championship) with no WebGL boot. |
| `vehicle-shots.mjs` | Vehicle showroom capture: boots the real menu once, sets the real `#vehicle` select for every machine, waits for a completed menu frame of that machine (`apexDiagnostics().menuPreview`) and saves a 1280x720 JPEG (<= 200 KB) each. `--reps` (one per class), `--all`, `--ids a,b`, `--prefix before`, `--skip-existing`, `--chrome` (keep the menu UI). Needs `npm run generate:player-lods` once in a fresh worktree. Output: `docs/studio/reports/vehicle-screens/`. |
| `car-lab/` (`index.html`, `lab.ts`, `shots.mjs`) | CAR LAB: the production render classes (`FormulaCar` with the A61 levels and the authored driver, `VehicleBodies`, `BikeShells`) in a minimal studio scene (room IBL, one shadowed key) for fast close-ups from any named view (`front34`, `rear34`, `cockpit`, `helmet`, `wheelFront`, `wingRear`, `diffuser`, `bikeCorner` ...) with a pose (`--pose '{"steer":0.4,"brake":1,"discTemp":900,"lean":1.0}'`). `npx vite --port 4298 --host 127.0.0.1`, then `node scripts/studio/tools/car-lab/shots.mjs --url http://127.0.0.1:4298 --out <dir> --id apx01,gpr1 --views front34,rear34`. 20 to 60 s per machine on software GL. It is NOT the game's lighting (no sky, grade, DOF): compare lab shots with lab shots; the showroom captures (`vehicle-shots.mjs`) are the evidence for the final look. |
| `vehicle-sheet.py` | Contact sheet (cropped car region, labelled tiles) from vehicle-shots captures. |
| `vehicle-drive.mjs` | In-session capture (pick discipline:machine, start, hold keys, JPEG chase/cockpit shots). Reaches the festival HUD but SwiftShader cannot complete a screenshot of the open world: use on a GPU host. |
| `body-audit.mts` | Headless geometry audit of every catalogue body (size vs collision box, tyre radius, hub error, arch clearance): `npx vite-node scripts/studio/tools/body-audit.mts [id ...]`. |
| `uxdom.mjs` + `ux-fixture.ts` | Fast DOM-only screens of the real Interface (menu per discipline, pause, results, settings, controls, championship, `menuProgress`, `wildcardBoard`, `wildcardResult`) with no WebGL boot. |
| `ux2shots.mjs` | Wave-2 real-game shots in one boot: menu per discipline, the LIGHT dial, the Wildcard board, and a race (loading, briefing, HUD, pause) from the board or the form. |
| `ux-fixture.ts` wave-3 scenes | `career`, `careerPlayed`, `careerLadder` (the season board: new driver, a played career, scrolled to the ladder), `firstRun`, `resultsCareer` (podium, payment, next step), `shareCard` (the PNG a player saves), `settingsGuide`, `team`, `photo`, `replay`, `loadingScreen`. Run with `node scripts/studio/tools/uxdom.mjs OUT PREFIX scene,scene`. |
| `firstrun.mjs` | G3 probe for the first-launch screen: the real game with `?firstrun=1`, counts the inputs from the screen to the first driving frame and saves the screen and the driving HUD. Software GL: times are an upper bound. |
| `ux3shots.mjs` | Wave-3 real-game shots in one boot: paddock, season board (CAREER), the settings graphics guide with its frame rate and GPU suggestion, Team HQ; reports errors. |
| `store-shots.mjs` | STORE SCREENSHOT DIRECTOR: boots the real game and captures 1920x1080 JPEG (q88) hero shots of curated moments (menu board, Wildcard board, formula in fog at golden hour, GP bike corner, motocross jump, snow pass, night street rain, results board, photo studio, festival coast) into `docs/studio/store/screenshots/` with `manifest.json` (alt text, status, notes) and `progress.log`. Resumable (`--only`, `--force`, `--reject id --reason`, `--manifest-only`, `--list`, `--budget-minutes`), one browser, software GL (minutes per shot; run under `nice` in the background). In-session frames are parked with the game's replay: a low-resolution scan of the recording picks the moment (deepest lean, middle of the longest flight), then the viewport grows to 1080p for the shot. Serve the FULL build (`npx vite preview --outDir dist --port 4242`). |
| `demo-check.mjs` | Steam demo edition check in the real game (one boot): FULL GAME plate, locked venue and machine lists per plate, a refused locked session, the Wildcard board with locked plates, the career licences page; JPEG evidence plus a JSON report. Serve `dist-demo` (`npx vite preview --outDir dist-demo --port 4242`). |
| `uxdom.mjs` scenes `records`, `recordsWildcard`, `demoMenu`, `demoWildcard` | The RECORDS screen (local leaderboards, with synthetic laps) and the Steam demo's paddock and Wildcard board, DOM-only (no WebGL). |
| `pw-dom.config.ts` | Playwright config for the DOM-only component specs (`e2e/60-launch-board`, `44-motocross-interface`): no server, no WebGL check. |
| `quickstart.mjs` | Menu-to-driving probe counting inputs (G3). Software GL on a shared host is far slower than hardware: the time is an upper bound. |
| `flashcheck.mjs` | End-to-end flashback check in a live session. |
| `fastcheck.sh <area>` | Per-area vitest subsets (render, world, car, character, ui, assets, sim). |
| `journey.mjs` | FULL-FLOW QA: menu -> configure -> start -> keyboard drive -> pause -> resume -> results -> exit -> second session, for `formula-practice`, `formula-race`, `time-trial`, `gp-race`, `wildcard`, `festival`, and the dirt journeys `motocross` (OUTDOOR MX), `supercross` (STADIUM SX) and `rallycross` (`--list`). The dirt bike journeys ride on the in-game AI DRIVER (G) from the gate (`drive({ startAuto: true })`): that proves the route, a running session, pause, results, exit and the AI's riding, not that a human can steer a dirt bike. Records timings, console/page errors, simulation snapshots tapped from the physics worker, screenshots, memory, optional CPU profiles (`--profile`) and machine-checked findings into `--out`. Run with `node --no-warnings --experimental-transform-types scripts/studio/tools/journey.mjs --journey <name> --out <dir> [--url ...] [--quality low]`. |
| `keyboard-driver.mjs`, `driver-selftest.mjs` | The journey tool's closed-loop digital driver (throttle/brake/left/right from centreline pursuit) and its headless tuning harness against the production `Simulation` (`... driver-selftest.mjs aurel apx01 150 practice`). Tuned for four-wheel cars; it cannot hold a GP bike on keyboard steering. |
| `journey-summary.mjs`, `journey-evidence.py`, `profile-callers.mjs`, `ai-only-race.mjs` | Digest of a journey directory; copy it into the repo as JPEG + JSON evidence; attribute a CPU profile's hot native calls to their JS callers; an all-AI control race (`... ai-only-race.mjs kansai-east gpr1 4 3 73021`) to tell an AI fault from one the player caused. |
| `bike-ai-sweep.ts` | Headless all-AI bike race sweep (no browser, 5 to 12 s per 4-bike 3-lap race): falls per bike, race and best-lap times, and with `--trace` every fall's lap time, station, speed, lean, tyre use, pedals and the line that raised it. `node --no-warnings --experimental-transform-types scripts/studio/tools/bike-ai-sweep.ts kansai-east,ardennes gpr1 4 3 5000 10 --trace`. Run it from two checkouts to compare before/after a bike AI or bike physics change. |
| `audio-render.mjs` + `audio-fixture.ts` + `audio-scenarios.ts` + `audio-analyze.py` + `audio-compare.py` | OFFLINE AUDIO MEASUREMENT RIG: bundles the production audio graph (`RacingAudio`, `UiSounds`, the driving-cue tones) with vite, renders ~370 scenarios (every engine class idle / mid / redline / lift / gear change / pull / rev limiter / pit limiter, tyre squeal, nine surfaces, wind, rain / storm / snow / dust / fog, collisions, landings, start lamps, a 12-car grid, full mixes and their engine / effects / ambience stems, menu sounds) into an `OfflineAudioContext` in headless Chromium, writes 32-bit float WAVs and analyses them with numpy: peak and true peak, K-weighted LUFS, spectral centroid, harmonic profile, pitch tracking against the firing frequency, clicks, level steps, gear-change dips, mono fold-down, distinctness heat map, spectrogram PNGs. `--live` also checks the real AudioContext under the autoplay policy (resume stays pending without a gesture; unlock on a click; review tap). `node --no-warnings scripts/studio/tools/audio-render.mjs --out <dir> --stems --live`; compare two runs with `python3 -I scripts/studio/tools/audio-compare.py <before>/analysis.json <after>/analysis.json`. Needs only numpy and Pillow. Every figure is a numeric proxy: see `docs/studio/reports/audio.md`. |
| `machine-benchmark.ts` | Handling & calibration benchmark of EVERY machine (57): 0-100, 0-200, top speed, 100-0, closed-loop skidpad lateral g at 50 m and 150 m, understeer gradient and lift-off / full-throttle rotation (cars), a coasting slalom exit speed, mass and power, one production-AI reference lap on Aurel (and on a dirt / rallycross venue for off-road machines). Judges each against general-knowledge class sanity bands (NOT licensed data), flags outliers, gearbox hunting, lap-order breaks and near-identical pairs. `node --no-warnings --experimental-transform-types scripts/studio/tools/machine-benchmark.ts [--ids a,b] [--no-laps] [--merge] [--baseline before.json] [--out docs/studio/reports/machine-benchmark]` writes `<out>.json` and `<out>.md`; a full run is 15 to 25 minutes of one CPU. |
| `bike-ai-sweep.ts` | Headless all-AI bike race sweep (no browser, 5 to 12 s per 4-bike 3-lap race): falls per bike, race and best-lap times, and with `--trace` every fall's lap time, station, speed, lean, tyre use, pedals and the line that raised it. `node --no-warnings --experimental-transform-types scripts/studio/tools/bike-ai-sweep.ts kansai-east,ardennes gpr1 4 3 5000 10 --trace`. Run it from two checkouts to compare before/after a bike AI or bike physics change. A comma list of vehicles is a mixed grid: each line then also carries the planner's completed passes and abort reasons per rider, the best lap per vehicle type, the net position swaps between types (`"gpr1>sbk1000"`) and the race-control incident count; `--seeds=a,b,c` re-runs listed seeds. Falls are rare, so every line also counts two leading indicators: `slides` (episodes of a GP rear stepping out, lateral speed above 3 m/s at more than 20 m/s) and `offTrack` (episodes of a bike past the edge of the road), and `limits`, how often each traffic-planner rule (`follow`, `settle`, `clear`, `close`, ...) set a speed limit. |
| `bike-fall-trace.ts` | Frame-by-frame trace of every fall in one seeded bike race (any field, e.g. mixed `gpr1,sbk1000,...`): for the last `window` s before each fall, the faller's lap distance, lateral position against the road, planned lane against the racing line, speed, lean against its limit, pedals, the traffic planner's cap and the rule that set it, the line's curvature and distance to the next corner, gap / lateral offset / closing speed to the rider ahead, the planner's decision, blocker and pass target; plus the rider it was following. `node --no-warnings --experimental-transform-types scripts/studio/tools/bike-fall-trace.ts montejaral 5000 gpr1,sbk1000,gpr1,sbk1000,gpr1,sbk1000 2 8 0.25`. Use it on the races `bike-ai-sweep.ts --trace` names. |
| `e2e-sweep.mjs` + `pw-sweep.config.ts` + `e2e-sweep-queue.json` | E2E REGRESSION SWEEP: runs the browser suite one spec at a time (one Playwright process, one browser), resumable (`--log` JSONL of finished specs, skipped on restart), per-spec stdout and Playwright JSON under `--logs`, a priority-ordered queue of all 133 specs (`dom` = fixture specs that need no server, `real` = preview server on `--port`, entries may carry `grep` / `grepInvert` / `env`). `npm run build` first; then `node scripts/studio/tools/e2e-sweep.mjs --queue scripts/studio/tools/e2e-sweep-queue.json --log <progress.jsonl> --logs <dir> --port 4251 [--stop-at <epoch ms>] [--only <substring>] [--force]`. `pw-sweep.config.ts` keeps the repo's 300 s / 60 s deadlines (`APEX_TIMEOUT_MS` / `APEX_EXPECT_TIMEOUT_MS` only ever lengthen them, to time a wait that overran on software GL). The results of the first sweep are in `docs/studio/reports/e2e-sweep.json`. |
| `hud-measure.mjs` + `hud-legibility.page.js` | HUD LEGIBILITY MEASUREMENT (DOM only, no WebGL): the on-screen size of every text the race HUD draws (own text nodes and `::before` / `::after` text, times every `transform: scale` and CSS `zoom` above it) for the circuit, GP bike, dirt and open-world HUDs and the states a plain frame does not show (race-control banner, pit lane, start lights, vehicle warning, VEHICLE panel, GP corner guide: `ux-fixture.ts` `hudState`), at 1280x800, 1280x720, 1920x1080 and 3840x2160 (`--viewports`), against the tier floors in the page script (primary readouts 18 px, labels 11 px, microcopy 10 px, the wordmark exempt). `node scripts/studio/tools/hud-measure.mjs --out <dir> --label after [--scenes hud,hudGp,...] [--hud-scale auto\|1\|1.15\|1.3\|1.5] [--shots] [--list]` writes `<label>-hud-measure.json` (every row) and `.md` (the table), prints the rows under their floor. The page script's `layout()` (panels on screen, overlaps, panels outside the window, panels in the sight window, clipped text) is what `e2e/65-hud-legibility.spec.ts` asserts. |
| `hud-real.mjs` | One real-game HUD frame (software GL, one browser): the first-launch path (`?firstrun=1`) to the first driving frame of a circuit session at `--viewport 1280x800`, a JPEG and the same text measurement taken in the real page. `node scripts/studio/tools/hud-real.mjs --url http://127.0.0.1:4311 --out <dir> --prefix after [--hud-scale 1.3]`. |
| `hud-cvd.mjs` | Colour-vision-deficiency check of the HUD's colour-coded accents (tyre temperature bands, timing colours, with and without the colour-blind setting): Machado 2009 protan / deutan / tritan simulation, CIE76 delta-E of the worst pair per viewer. `node scripts/studio/tools/hud-cvd.mjs [--json]`; `tests/hud-colourblind.test.ts` holds the verdicts. |
| `board-measure.mjs` | Where the Paddock Board's left panel spends its height at a viewport (and an optional screenshot): `node scripts/studio/tools/board-measure.mjs 1280 720 out.png`. |
| `pw-port.config.ts` | Playwright config for a worktree build on a private port (`APEX_WT`, `APEX_PORT`). |
| `stats.py`, `px.py`, `crop.py`, `mergeshots.py`, `frametimes.py` | Image crop statistics, pixel probes, montages and frame-time extraction from capture `diag.json`. |

The canonical capture and KPI tools are `scripts/studio/capture-matrix.mjs`, `look-metrics.py`,
`shotdiff.py` and `signoff.mjs`.
